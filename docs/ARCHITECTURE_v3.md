# Архитектура v3: универсальный контент-конвейер для нескольких проектов

Дата: 2026-10-08. Развивает [`AUDIT_v2.md`](AUDIT_v2.md): там один проект, здесь — одно ядро и много проектов. Факты об API соцсетей — в [`AUDIT.md`](AUDIT.md), раздел 1. Код пока не пишется.

---

## 1. Анализ предложенной архитектуры

Идея «одно ядро + проекты с настройками + один бот» верная. Все три примера (Зазеркалье, Петербург, Приложения) проходят **через один и тот же конвейер**:

```
материал → анализ → генерация полей → (озвучка) → (видео) → тексты по площадкам → превью → публикация
```

Различаются они не кодом, а **данными**:
- **что извлечь из материала** — билет ПДД / место и заведение / рекламируемое приложение;
- **какие поля сгенерировать** — тизер + разбор / факты + адрес + часы / рекламный сценарий;
- **как собрать пост для каждой площадки** — Telegram с ответом, остальные без; с адресом или без;
- **голос, стиль, CTA, хэштеги, аккаунты**.

Значит, всё различие можно вынести в конфигурацию. Для этого ядро должно уметь **три вещи**, которых не было в v2:

1. **Динамическая схема генерации.** Ядро не знает заранее полей «правильный ответ» или «график работы». Список полей и их описания задаёт сценарий, а ядро на лету собирает из них JSON Schema для структурированного ответа Claude.
2. **Шаблоны постов по площадкам.** Текст каждой площадки — это шаблон, который ссылается на сгенерированные поля. Так «Telegram с ответом, TikTok без ответа» становится разницей в шаблоне, а не в коде.
3. **Конвейер из шагов-кубиков.** Сценарий перечисляет шаги из реестра ядра (`analyze`, `generate`, `tts`, `render_video`, …) и их параметры.

### Что в предложенной схеме нужно уточнить

| Пункт | Проблема | Решение |
|---|---|---|
| «Выберите проект» на каждый материал | лишнее нажатие, если вы весь день работаете с одним проектом | кнопки проектов отсортированы по недавнему использованию + **«липкий» проект** (последний выбранный предлагается первым) + быстрый выбор по подписи (`#питер`) |
| Сценарии внутри проекта | вы не хотите каждый раз выбирать «кафе / здание / мероприятие» | Claude **сам определяет сценарий** по материалу (дешёвый шаг классификации); кнопка «сменить сценарий» в превью |
| Видео на входе (проект «Приложения») | Claude не принимает видео напрямую | ядро извлекает ключевые кадры (FFmpeg) и, если в видео есть речь, расшифровку (STT). Это шаг `extract_video`, а не отдельная система |
| Факты: адрес, часы работы (Петербург) | LLM **будет выдумывать** часы и адреса | отдельный шаг обогащения с источником (поиск в вебе или API карт) и обязательной пометкой «проверь» в превью. Без источника поле остаётся пустым |
| Реклама (проект «Приложения») | площадки требуют помечать коммерческий контент (у TikTok это часть обязательного UX Direct Post) | признак `commercial: true` в проекте → ядро само выставляет флаги раскрытия на каждой площадке |
| Несколько аккаунтов одной соцсети | токены, лимиты и аудиты считаются по-разному | подключения к соцсетям — отдельная сущность, привязанная к проекту (см. раздел 3.3) |

## 2. Организация: проекты, сценарии, настройки

Четыре уровня. Каждый следующий уточняет или переопределяет предыдущий:

```
СИСТЕМА (глобальные настройки, ключи API, реестр шагов и площадок)
   └── ПРОЕКТ (бренд: стиль, голоса, аккаунты, площадки, правила по умолчанию)
          └── СЦЕНАРИЙ (тип контента: шаги, поля для генерации, шаблоны постов)
                 └── ЗАПУСК / ПОСТ (конкретный материал + ваши правки)
```

Значения наследуются: **запуск → сценарий → проект → система**. Например, голос задан в проекте, но сценарий «диалог» может его переопределить, а в превью вы можете сменить его только для этого поста.

### Сущности

| Сущность | Что это | Где хранится |
|---|---|---|
| **System** | ключи API, модели по умолчанию, лимиты расходов, владелец бота | `.env` + глобальный конфиг |
| **Project** | бренд/аккаунт: «Зазеркалье», «Петербург» | БД (документ JSON, с версиями) + экспорт/импорт YAML |
| **Scenario** | тип поста внутри проекта: «билет ПДД», «кафе», «рекламный ролик» | внутри проекта |
| **Template** (шаблон проекта) | готовая заготовка проекта или сценария, которую клонируют: «викторина с тизером», «место/заведение», «реклама приложения» | файлы YAML в репозитории |
| **Connection** | подключённый аккаунт соцсети: OAuth-токены, ID канала | БД, токены зашифрованы |
| **Asset** | файлы проекта: фото персонажей, логотип, музыка, примеры удачных постов | R2 + ссылка в проекте |
| **Run** | один запуск конвейера: материал, выбранный проект и сценарий, результаты шагов, правки | БД + R2 |
| **Publication** | результат публикации на одной площадке: статус, ссылка, ошибка | БД |

## 3. Общие и проектные параметры

### 3.1 Общие для всей системы (одно значение на всех)

| Параметр | Почему общий |
|---|---|
| Ключи API: Anthropic, ElevenLabs, Gemini, R2, Telegram-бот | один счёт, одна точка смены ключа |
| Приложения платформ: Meta App, TikTok App, Google OAuth client (client id/secret) | приложение одно, к нему подключается много аккаунтов |
| Ключ шифрования токенов | безопасность |
| Список пользователей бота и роли (сейчас — только вы) | доступ |
| Модели по умолчанию (Claude, TTS, image) и их цены | для учёта расходов |
| Лимит расходов в день/месяц, алерты | защита бюджета |
| Технические пресеты рендера (кодеки, битрейт, `faststart`, размеры под площадки) | требования площадок одинаковы для всех проектов |
| Реестр шагов конвейера и адаптеров площадок | это и есть код ядра |
| Часовой пояс, язык интерфейса бота | — |
| Политика хранения файлов (сколько дней держать черновики) | — |

### 3.2 Отдельно для каждого проекта

| Группа | Параметры |
|---|---|
| **Идентичность** | `id`, название, эмодзи для кнопки, описание, аудитория, язык(и) контента |
| **Голос бренда** | стиль, тон, допустимый юмор, запретные темы и слова, примеры удачных постов (few-shot) |
| **Знания проекта** | персонажи (Батракан, Педаль: внешность, характер, манера речи), глоссарий, постоянные факты, ссылки |
| **Озвучка** | голос(а) по умолчанию, голоса персонажей, скорость, стиль подачи, включена/выключена |
| **Площадки** | какие включены; для каждой — привязанное подключение (аккаунт/канал), формат (фото/видео/фото-пост), хэштеги, CTA, режим TikTok (черновик/прямой), видимость YouTube |
| **Визуал** | шаблон видеообёртки (размытый фон, зум), логотип/плашка, фоновая музыка |
| **Режим публикации** | ручное подтверждение / АВТО с таймером / АВТО; расписание (например, «не раньше 18:00»), минимальный интервал между постами |
| **Коммерция** | `commercial: true/false` → пометки рекламы на площадках |
| **Сценарии** | список сценариев (раздел 4) и правило выбора по умолчанию |
| **Модели (переопределение)** | например, Opus для сложного проекта, Haiku для простого |

### 3.3 Подключения к соцсетям: отдельная сущность

Проект ссылается на подключение, а не хранит токен сам. Так один аккаунт можно использовать в двух проектах, а при смене пароля переподключается только он.

| Площадка | Как это ложится на мультипроектность | Ограничение, которое важно для нескольких аккаунтов |
|---|---|---|
| Telegram | один бот — администратор в нескольких каналах; у проекта свой `channel_id` | нет |
| Instagram | одно Meta App, отдельный OAuth-токен на каждый профессиональный аккаунт | Standard Access подходит только для аккаунтов, которыми вы **владеете или управляете**; токен живёт 60 дней, обновлять каждый |
| TikTok | одно приложение, отдельный токен на аккаунт | **до аудита — не более 5 пользователей за 24 часа**: при 3–4 аккаунтах хватает, но запаса почти нет |
| YouTube | один OAuth-клиент, отдельный токен на каждый канал | квота загрузок (100 в день по текущим данным) общая на весь Google-проект; до аудита — только приватные видео |

## 4. Структура конфигурации проекта

Хранится в БД как документ, проверяется по строгой схеме (Pydantic) при каждом сохранении. Ниже — представление в YAML (для экспорта, импорта и шаблонов).

### 4.1 Пример: «Зазеркалье»

```yaml
id: zazerkalye
name: Зазеркалье
emoji: "🪞"
description: Мемный образовательный проект про ПДД с персонажами Батракан и Педаль
language: ru
commercial: false

brand:
  tone: мемный, дерзкий, но без грубости; короткие фразы
  audience: водители и будущие водители 16–35
  avoid: [канцелярит, морализаторство, политика]
  examples:                       # few-shot: 3–5 лучших постов
    - asset: examples/post_017.json

knowledge:
  characters:
    - name: Батракан
      description: ...
      voice: voice_batrakan       # ID голоса ElevenLabs
    - name: Педаль
      description: ...
      voice: voice_pedal
  facts_policy: "Ответ на билет — только по ПДД РФ. Если не уверен — пометь uncertain: true"

voice:
  enabled: true
  default_voice: voice_batrakan
  speed: 1.05

platforms:
  telegram:
    connection: tg_zazerkalye_channel
    format: photo                 # photo | video | text
    template: telegram_full       # шаблон из сценария
  instagram:
    connection: ig_zazerkalye
    format: video                 # Reels с озвучкой
    template: teaser
    hashtags_fixed: ["#зазеркалье", "#пдд"]
  tiktok:
    connection: tt_zazerkalye
    format: video
    mode: draft                   # draft до аудита → direct
    template: teaser
  youtube:
    connection: yt_zazerkalye
    format: video
    template: teaser_youtube

publishing:
  approval: manual                # manual | auto_timer | auto
  auto_timer_minutes: 15

scenario_selection: auto          # auto | ask | default
default_scenario: pdd_ticket

scenarios:
  - id: pdd_ticket
    extends: template:quiz_teaser # наследуем общий шаблон «викторина с тизером»
    title: Билет ПДД
    when: "На изображении билет ПДД / дорожная ситуация с вопросом"
    instructions: |
      Распознай вопрос и варианты. Определи правильный ответ и объясни со ссылкой на пункт ПДД.
      Тизер — от лица Батракана, ответ НЕ раскрывать.
    fields:                       # что сгенерировать (→ JSON Schema для Claude)
      question:     {type: string, desc: "Вопрос билета своими словами"}
      correct:      {type: string, desc: "Правильный вариант"}
      rule_ref:     {type: string, desc: "Пункт ПДД"}
      explanation:  {type: string, desc: "Разбор в стиле проекта, 3–6 предложений"}
      teaser:       {type: string, desc: "Хук-вопрос без ответа, до 150 символов"}
      voiceover:    {type: string, desc: "Текст озвучки 15–20 с, без ответа"}
      uncertain:    {type: boolean, desc: "Есть сомнения в ответе"}
    steps: [analyze, generate, tts, render_video, compose]
    checks:
      - field: uncertain
        equals: true
        action: block_auto        # не публиковать автоматически, подсветить в превью
```

### 4.2 Пример: «Петербург» (только отличия)

```yaml
id: spb
name: Петербург
emoji: "🏙"
brand: {tone: "информативный, живой, без канцелярита"}
voice: {enabled: true, default_voice: voice_anna}
platforms:
  telegram:  {connection: tg_spb, format: photo, template: post_full}
  instagram: {connection: ig_spb, format: photo, template: post_short}
  tiktok:    {connection: tt_spb, format: video, template: post_short}
scenario_selection: auto
scenarios:
  - id: venue
    extends: template:place
    title: Кафе / заведение
    when: "Заведение: кафе, бар, ресторан, магазин"
    fields:
      name:     {type: string}
      address:  {type: string, source: enrich, verify: true}   # не выдумывать — брать из источника
      hours:    {type: string, source: enrich, verify: true}
      facts:    {type: array, items: string, desc: "2–3 интересных факта"}
      hook:     {type: string}
    steps: [analyze, enrich_place, generate, tts, render_video, compose]
  - id: building   {extends: template:place, title: Здание, ...}
  - id: event      {extends: template:event, title: Мероприятие, ...}
  - id: collection {extends: template:collection, title: Подборка, multi_media: true, ...}
```

### 4.3 Шаблоны постов по площадкам

Шаблон — это текст с подстановкой полей (Jinja2 в безопасном режиме). Его можно задать вручную или поручить Claude («перепиши под площадку по правилам»):

```yaml
templates:
  telegram_full: |
    {{ teaser }}

    <tg-spoiler>✅ {{ correct }}</tg-spoiler>
    {{ explanation }}
    📖 {{ rule_ref }}
  teaser:
    mode: llm                     # Claude пишет под площадку, но только из полей teaser/question
    allowed_fields: [teaser, question]   # гарантия: ответ не попадёт в тизер
    rules: "Хук + вопрос к зрителю + CTA «ответ в Telegram»; 3–5 хэштегов"
```

`allowed_fields` — **важная гарантия для логики тизера**. Модель, которая пишет текст для TikTok, физически не получает поля `correct` и `explanation`, поэтому не может раскрыть ответ даже по ошибке. Дополнительно ядро проверяет, что текст ответа не встречается в тизере.

## 5. Как добавлять проекты без изменения ядра

### 5.1 Граница между кодом и данными

| Что вы добавляете | Нужен код? | Как |
|---|---|---|
| **Новый проект** | ❌ нет | `/new_project` в боте или YAML |
| **Новый сценарий** в проекте | ❌ нет | поля + инструкции + шаблоны + шаги из реестра |
| Новый голос, хэштеги, CTA, площадка из уже поддерживаемых | ❌ нет | настройки проекта |
| Новый **шаблон проекта** (тип контента для повторного использования) | ❌ нет | YAML-файл в `templates/` |
| Новый **тип шага** (например, «погода», «курс валют», «карты») | ✅ да, один модуль-плагин | реализовать интерфейс `Step` и зарегистрировать |
| Новая **соцсеть** (VK, Threads, Pinterest) | ✅ да, один модуль-адаптер | реализовать интерфейс `Publisher` |

Ядро меняется только когда появляется **новая возможность**, а не новый проект. Даже тогда это один модуль по фиксированному интерфейсу, без правок остального кода.

### 5.2 Механизмы, которые это обеспечивают

1. **Реестр шагов (plugin registry).** Каждый шаг — класс с одинаковым интерфейсом: `name`, схема параметров, `run(context) → outputs`. Сценарий ссылается на шаги по имени. Базовый набор:

   | Шаг | Что делает |
   |---|---|
   | `ingest` | приём фото/видео/альбома, нормализация (EXIF, формат) |
   | `extract_video` | ключевые кадры + расшифровка речи для видео на входе |
   | `classify` | выбор сценария проекта по материалу (если `scenario_selection: auto`) |
   | `analyze` | Claude: что на материале (общее описание + поля сценария `source: vision`) |
   | `enrich_*` | внешние данные с источником (веб-поиск / карты); результат помечается «проверить» |
   | `edit_image` | Gemini Image по референсу (сценарий «исходник + референс») |
   | `generate` | Claude: поля сценария по динамической JSON Schema |
   | `tts` | озвучка (один голос или диалог персонажей) |
   | `render_video` | FFmpeg: видеообёртка или наложение озвучки на исходное видео |
   | `compose` | сборка текстов по шаблонам каждой площадки + хэштеги |
   | `validate` | проверки: длины, запрещённые слова, утечка ответа в тизер, `uncertain` |
   | `publish` | отправка через адаптеры площадок |

2. **Динамическая JSON Schema.** Ядро строит схему из `fields` сценария и передаёт её Claude через structured outputs. Ядро не знает, что такое «правильный ответ» — оно знает только, что сценарий попросил поле `correct` типа `string`.

3. **Адаптеры площадок (Publisher).** Единый интерфейс: `capabilities()` (фото/видео/альбом, лимиты длины, нужна ли публичная ссылка), `validate(post)`, `publish(post, connection) → {url, id}`. Проект говорит только «tiktok, format: video, mode: draft».

4. **Наследование конфигураций.** `extends: template:quiz_teaser` — сценарий берёт поля, шаги и шаблоны из общего шаблона и переопределяет только своё. Новый «викторинный» проект (например, про медицину или историю) — это 10 строк.

5. **Валидация и версии.** Каждое сохранение проекта проверяется по схеме (опечатка в имени шага → понятная ошибка, а не падение в 3 часа ночи). Хранятся версии: можно откатиться, а у каждого поста записано, на какой версии конфига он сделан.

6. **Пробный запуск.** `/test` прогоняет конвейер проекта на материале **без публикации** — так новый проект проверяется до подключения к реальным аккаунтам.

### 5.3 Как работает `/new_project`

Форму из 10 полей в Telegram заполнять неудобно. Удобнее диалог, где Claude сам собирает конфигурацию:

```
Вы:  /new_project
Бот: Опишите проект в свободной форме (можно голосом).
Вы:  Петербург. Аккаунт про интересные места СПб. Стиль информативный, живой,
     без канцелярита. Голос — Анна. Instagram, TikTok, Telegram.
     Сценарии: кафе, здания, мероприятия, подборки.
Бот: (Claude превращает описание в YAML по схеме, берёт подходящие шаблоны:
      кафе → template:place, мероприятия → template:event, подборки → template:collection)
     Вот проект:
     🏙 Петербург · ru · голос Анна · IG/TikTok/TG
     Сценарии: Кафе (адрес и часы — с проверкой) · Здание · Мероприятие · Подборка
     Не хватает: аккаунтов Instagram и TikTok, канала Telegram.
     [✅ Создать] [✏️ Изменить] [🔗 Подключить аккаунты] [🧪 Тест на фото]
```

Подключение аккаунтов — по ссылке OAuth из бота (открывается в браузере) или выбором уже подключённого аккаунта. Канал Telegram — добавить бота администратором и переслать боту любое сообщение из канала.

Редактирование: `/project spb` → кнопки разделов, или текстом: «в Петербурге добавь хэштег #спб и убери TikTok». Claude вносит изменение, бот показывает разницу «было → стало» и просит подтвердить.

## 7. Что переиспользуем из системы «Зазеркалья» как первый шаблон

**Важно:** кода «Зазеркалья» в репозитории нет, есть только проект в `AUDIT_v2.md`. Если у вас где-то есть уже работающие скрипты, промпты или бот (возможно, это `STORY.md`), пришлите их — разберу, что из них перенести.

Из спроектированного переиспользуется **почти всё**, но разделённое на «ядро» и «данные»:

| Часть системы «Зазеркалья» (v2) | Куда переходит в v3 |
|---|---|
| Telegram-бот, превью, кнопки, правки ответом | **ядро** (общий интерфейс для всех проектов) |
| Нормализация картинки (Pillow) | ядро, шаг `ingest` |
| Один запрос Claude → тексты для 4 площадок | ядро, шаги `generate` + `compose`, но с полями из сценария вместо зашитых |
| Озвучка ElevenLabs | ядро, шаг `tts` (+ диалоги персонажей) |
| FFmpeg-видеообёртка (картинка + размытый фон + зум + голос) | ядро, шаг `render_video`; параметры обёртки — в проекте |
| Адаптеры Instagram / TikTok / Telegram / YouTube | ядро, адаптеры `Publisher` |
| R2, журнал, шифрование токенов, повторы при ошибках | ядро, без изменений |
| Режим АВТО с таймером | ядро; включение — настройка проекта |
| **Логика тизера (ответ только в Telegram)** | **шаблон `quiz_teaser`**: поля `teaser`/`answer`/`explanation`, `allowed_fields` для площадок без ответа, проверка утечки ответа — подходит для любого викторинного проекта |
| Распознавание билета ПДД, ссылки на пункты ПДД | сценарий `pdd_ticket` проекта «Зазеркалье» (данные) |
| Персонажи Батракан и Педаль, их голоса | `knowledge.characters` проекта «Зазеркалье» (данные) |
| Мемный стиль, хэштеги, CTA | `brand` и `platforms` проекта (данные) |
| Правило «не публиковать автоматически, если ответ сомнительный» | общий механизм `checks` → `block_auto` |

Из «Зазеркалья» получаются **два артефакта**: сам проект `zazerkalye` и переиспользуемый шаблон `quiz_teaser`. Второй шаблон, `place`, появится из Петербурга, третий, `ad_promo`, — из Приложений.

### Шаблоны, с которых стоит начать

| Шаблон | Для чего | Ключевые особенности |
|---|---|---|
| `quiz_teaser` | Зазеркалье и любые викторины | тизер без ответа + полный разбор в Telegram, проверка утечки |
| `place` | Петербург: кафе, здания | шаг `enrich` для адреса и часов с обязательной проверкой |
| `event` | мероприятия | дата, место, ссылка, «актуально до» |
| `collection` | подборки (несколько фото) | альбом/карусель, по полю на каждый пункт |
| `ad_promo` | Приложения | видео на входе, рекламный сценарий (хук → проблема → решение → CTA), `commercial: true`, пометки рекламы на площадках |
| `simple_post` | любой новый проект «по умолчанию» | описание + хэштеги + CTA, без особой логики |

## 8. Изменения по сравнению с v2

| Что | v2 (один проект) | v3 (много проектов) |
|---|---|---|
| Промпты | зашиты в код | в конфигурации проекта и сценария |
| Поля генерации | фиксированные | динамические, из `fields` сценария |
| Тексты площадок | один промпт на все | шаблоны + `allowed_fields` на каждую площадку |
| Аккаунты соцсетей | по одному на площадку | сущность `Connection`, привязка к проекту |
| Вход | только фото | фото, видео, альбом (`extract_video`) |
| Внешние факты | не было | шаг `enrich` с источником и пометкой «проверить» |
| Новый проект | правка кода | `/new_project` или YAML |
| БД | SQLite | SQLite остаётся достаточной; PostgreSQL — при добавлении других пользователей |

Дополнительные расходы на один пост: шаг `classify` (~$0.001 на Haiku), `enrich` (веб-поиск — ⚠️ проверить цену), `extract_video` + STT для видео на входе (⚠️ ~копейки за минуту). Порядок цены поста из v2 сохраняется: **≈ $0.01–0.10**.

## 9. Риски каркаса

1. **Переусложнение конфигурации.** Если сделать «универсальный язык» для всего, настраивать проекты станет сложнее, чем писать код. Решение: шаблоны + наследование + `/new_project` через Claude. Вы почти никогда не правите YAML руками.
2. **Выдуманные факты** (адреса, часы, ответы на билеты) — главный риск для доверия к аккаунтам. Решение: `source: enrich` + `verify: true` + `checks` → без подтверждения такие поля не публикуются автоматически.
3. **Публикация не в тот аккаунт.** Решение: жёсткая привязка запуска к проекту и явный список аккаунтов на кнопке подтверждения.
4. **Лимиты TikTok до аудита** (5 пользователей за 24 часа) при росте числа аккаунтов. Решение — подать на аудит заранее.
5. **Реклама:** без пометки коммерческого контента возможна блокировка поста или аккаунта. Решение — флаг `commercial` проставляет пометки автоматически.
