# Технический аудит: система автоматического создания и публикации контента

Дата аудита: 2026-10-08. Код на этом этапе не пишется.

> **Как проверялись факты.** Прямое скачивание страниц документации (developers.facebook.com, developers.tiktok.com, developers.google.com, core.telegram.org) из рабочего окружения заблокировано сетевым прокси. Поэтому факты собраны через веб-поиск, ограниченный официальными доменами; ссылки ведут на первоисточники. Там, где официальные страницы противоречат друг другу или где цифры взяты из сторонних агрегаторов (часть цен AI-сервисов), это помечено **⚠️**. Всё, что помечено ⚠️, нужно перепроверить в консоли сервиса перед тем, как на это опираться.

| Тип аккаунта | Только **профессиональный аккаунт (Business или Creator)**. Личные аккаунты не поддерживаются | [Instagram API with Instagram Login](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/) |

| Фото / карусели / Stories | Фото — **только JPEG**, до 8 МБ, соотношение сторон от 4:5 до 1.91:1. Карусель — до 10 элементов, Reels в карусель вложить нельзя. | Требования к Reels | MP4/MOV, H.264/HEVC, 23–60 fps, ширина до 1920 px, рекомендуется 9:16, **от 3 с до 15 мин, до 300 МБ**, moov atom в начале файла (faststart) | там же |
| Как передаётся файл | Только **по публичному URL**: Instagram сам скачивает видео. Нужно временное публичное хранилище (например, presigned URL в R2/S3) | [Content Publishing](https://developers.facebook.com/docs/instagram-platform/content-publishing/) |

| App Review | **Standard Access** хватает для аккаунтов, которыми вы владеете или управляете (у аккаунта есть роль в приложении). **Advanced Access** (App Review + Business Verification) нужен только если приложением пользуются чужие аккаунты | [Overview](https://developers.facebook.com/docs/instagram-platform/overview/) |
| Лимит публикаций | ⚠️ Документация противоречит сама себе: в справочнике `content_publishing_limit` указано **50 публикаций за скользящие 24 часа**, в других местах встречается 100. **Вывод:** 🟢 **Полная автоматизация возможна официально** после одного входа через OAuth. Нужно: профессиональный аккаунт, Meta App с ролью для вашего аккаунта, задача по расписанию для обновления токена (например, раз в 30–45 дней) и публичный URL для видео. App Review для одного своего аккаунта не нужен (⚠️ уточнить в App Dashboard при настройке).

### 1.2 TikTok

| Вопрос | Ответ | Источник |
|---|---|---|
| Официальный API | **Content Posting API**, два режима: **Direct Post** (сразу в профиль, scope `video.publish`) и **Upload** (в черновики/«входящие» TikTok, scope `video.upload`; пользователь заканчивает публикацию в приложении) | [Content Posting API](https://developers.tiktok.com/products/content-posting-api/), [Scopes](https://developers.tiktok.com/docs/en/tiktok-api-scopes) |
| **Главное ограничение** | Пока приложение **не прошло аудит**, Direct Post публикует **только в режиме `SELF_ONLY` (видно только автору)**, публиковать могут не более **5 пользователей за 24 ч**, а аккаунт должен быть **приватным** в момент публикации. Иначе возвращается ошибка `unaudited_client_can_only_post_to_private_accounts` | [Direct Post](https://developers.tiktok.com/doc/content-posting-api-reference-direct-post), [Content Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines) |
| Аудит | Чтобы публиковать публично, нужен **аудит приложения в TikTok** (проверка соответствия ToS, UX-макеты). Сроки TikTok не публикует | [App Review FAQ](https://developers.tiktok.com/doc/getting-started-faq) |
| Обязательный UX (проверяется на аудите) | Перед публикацией вызвать `creator_info/query` и показать никнейм аккаунта. Пользователь сам выбирает приватность из списка, **без значения по умолчанию**. Обязательны превью, переключатели комментариев/дуэтов/стежков, раскрытие коммерческого контента. Добавлять свои водяные знаки нельзя. Если `creator_info` сообщает, что публиковать сейчас нельзя, попытку нужно остановить | [Content Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines), [Query Creator Info](https://developers.tiktok.com/doc/content-posting-api-reference-query-creator-info) |
| Лимит | ~15 постов в день на аккаунт через Direct Post (общий для всех приложений) | [Content Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines) |
| Видео | MP4 (рекомендуется), WebM, MOV; 23–60 fps; стороны 360–4096 px; **до 4 ГБ**; длительность — не больше `max_video_post_duration_sec` из `creator_info` (у всех минимум 3 мин) | [Media Transfer Guide](https://developers.tiktok.com/docs/en/content-posting-api-media-transfer-guide) |
| Способ загрузки | `FILE_UPLOAD` (чанками) или `PULL_FROM_URL` — для второго нужно **подтвердить владение доменом** (DNS или файл), редиректы не допускаются. Проще использовать `FILE_UPLOAD` | там же |
| Пометка AI-контента | ⚠️ В `post_info` есть флаг AI-generated content. Перед реализацией проверить точное имя поля в справочнике | [Direct Post](https://developers.tiktok.com/doc/content-posting-api-reference-direct-post) |

**Вывод:** 🟡 **Частично.**
- **До аудита:** официальный путь — режим **Upload**: видео с описанием попадает в черновики TikTok, а вы нажимаете «Опубликовать» в приложении (одно ручное действие). Direct Post до аудита публикует только приватно.
- **После аудита:** 🟢 полностью автоматическая публикация, но с обязательным экраном выбора приватности и настроек (одна галочка/выпадающий список — это требование TikTok, и он вписывается в ваш экран «Опубликовать везде»).
- ⚠️ **Риск:** TikTok может не одобрить приложение, если оно сделано «для личного пользования». Это нужно выяснить при подаче. Обходы (эмуляция телефона, неофициальные API) **не предлагаю**.

## 2. AI-часть

### 2.1 Анализ изображения и референса (LLM с vision)

**Рекомендация: Claude (Anthropic API).** Модель принимает несколько изображений в одном запросе (фото + референс), умеет читать текст на изображении, описывать композицию, стиль, свет, объекты и действия. Через структурированный вывод (`output_config.format`, JSON Schema) отдаёт строгий JSON-«бриф»: сцены, движения камеры, промпты для генерации изображения и видео, сценарий озвучки, описания для каждой площадки. Это центральный «режиссёр» конвейера.

| Модель | Цена ввод / вывод за 1M токенов | Роль |
|---|---|---|
| Claude Opus 5.5 (`claude-opus-5-5`) | $4 / $20 | качественный вариант: анализ референса + сценарий |
| Claude Sonnet 5.5 (`claude-sonnet-5-5`) | $2 / $10 | хороший баланс цены и качества |
| Claude Haiku 5.5 (`claude-haiku-5-5`) | $0.10 / $0.50 | бюджетный вариант, описания и хэштеги |

Цены — из актуальной справки Anthropic API (кэш от 2026-10-06). Один ролик ≈ 3 изображения + ~10k входных и ~3k выходных токенов, то есть **$0.002–0.10** в зависимости от модели. Источник: [Anthropic pricing](https://docs.claude.com/en/docs/about-claude/pricing).

Альтернатива — Gemini 3.x (vision тоже сильный). Но так как роль «режиссёра» и автора текстов на трёх языках у Claude — основная, двух поставщиков LLM держать не нужно.

Сравнение по остальным критериям:
- **Стабильность.** Все модели недетерминированы: 20–40% генераций могут потребовать перегенерации (оценка; закладываю коэффициент ×1.3–1.5 в бюджет). Поэтому кнопка «перегенерировать сцену» обязательна.
- **Скорость.** Асинхронные задачи, обычно от десятков секунд до нескольких минут на клип. Нужен опрос статуса или вебхук и фоновая очередь.
- **Коммерческое использование.** ⚠️ У платных API Google и Kling результаты, как правило, можно использовать коммерчески, но **условия нужно прочитать до запуска** (Google, например, добавляет водяной знак SynthID). Самих условий я не проверял — пункт в чек-листе перед MVP.

**Рекомендация:** адаптер с двумя провайдерами — **Veo 3.1 (Fast/Lite) как основной** (официальный нативный 9:16, понятные цены) и **Kling 3.0 как альтернатива** для сцен с людьми и динамикой. Аудиодорожку модели при сборке всё равно заменяем своей.

**Важная экономия:** не каждую сцену нужно генерировать AI-видео. Эффект Кена Бёрнса (zoom/pan по фото) и параллакс делаются в монтажном движке бесплатно. Типовой ролик: 1–2 AI-клипа и 2–3 анимированных фото.

### 2.5 Субтитры

Оптимальная схема — **без распознавания речи вообще**:
1. Текст озвучки известен заранее (его пишет Claude).
2. ElevenLabs `with-timestamps` возвращает время каждого символа → собираем слова и фразы.
3. Монтажный движок рендерит субтитры (в стиле TikTok — по 2–4 слова, подсветка текущего слова) прямо в видео.

Запасные варианты: если аудио пришло без таймкодов (другой TTS или голос, записанный пользователем), используется [ElevenLabs Forced Alignment](https://elevenlabs.io/docs/api-reference/forced-alignment/create) (`POST /v1/forced-alignment`, аудио + текст → таймкоды слов) или STT (Whisper / ElevenLabs Scribe) с word-level timestamps.

Дополнительно экспортируется `.srt` — YouTube принимает его отдельной дорожкой (через `captions.insert`).

⚠️ **Арабский язык (RTL)** — отдельный риск: в FFmpeg/libass арабский рендерится корректно только при сборке с HarfBuzz/FriBiDi. В Remotion (Chromium) RTL и арабская вязь работают «из коробки». Это один из аргументов за Remotion.

## 3. Монтаж

| Критерий | FFmpeg (filtergraph) | **Remotion** (React → видео) | Альтернативы (MoviePy, Shotstack/Creatomate — облачные API) |
|---|---|---|---|
| 1080×1920, 9:16 | да | да | да |
| Zoom/pan, переходы | да (`zoompan`, `xfade`), но неудобно и «дёргано» при сложных сценах | да, плавно, любые кривые и анимации | да / да (шаблоны) |
| Текст, анимированные субтитры | сложно | **сильная сторона** (CSS, шрифты, RTL) | средне / шаблоны |
| Превью в браузере до рендера | нет | **да** (`@remotion/player`): правки видны мгновенно, без перерендера | нет / частично |
| Музыка, ducking, нормализация громкости | да | да (аудио), громкость лучше доводить FFmpeg | да |
| Стоимость | бесплатно | **бесплатно для команды до 3 человек**; для компании 4+ — от $100/мес | платно за минуту рендера |
| Скорость рендера | очень быстро | медленнее (headless Chrome), 30 с ролика ≈ десятки секунд – минуты на VPS | зависит от сервиса |

Лицензия Remotion: [License & Pricing](https://www.remotion.dev/docs/license/pricing).

**Рекомендация: Remotion + FFmpeg.**
- **Remotion** — композиция ролика: сцены, Ken Burns, переходы, текст, субтитры, звуковые дорожки. Ролик описывается JSON-«таймлайном», который генерирует Claude и правите вы. Тот же таймлайн отображается в браузерном превью — это ровно ваш сценарий «посмотрел → поменял текст → увидел».
- **FFmpeg** — пост-обработка: нормализация громкости (`loudnorm`), ducking музыки под голос, перекодирование под требования каждой площадки (H.264, AAC, `+faststart`, битрейт ≤ 25 Мбит/с для Instagram), контроль размера (≤ 50 МБ для Telegram).

## 5. Хранение файлов

**Рекомендация: Cloudflare R2** (S3-совместимое). [Цены R2](https://developers.cloudflare.com/r2/pricing/): $0.015/ГБ·мес, **исходящий трафик бесплатный**, бесплатно 10 ГБ·мес. Отсутствие платы за трафик важно: Instagram скачивает каждый ролик по URL, а превью вы смотрите много раз.

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| Локальный диск VPS | просто, бесплатно | нет публичного URL для Instagram без доп. настройки, риск потери, не масштабируется | только для временных файлов рендера |
| **Cloudflare R2** | дёшево, без платы за egress, S3 API, presigned URL | — | **основное хранилище** |
| AWS S3 | эталон S3 | платный egress | избыточно |
| Supabase Storage | удобно, если БД тоже на Supabase | дороже на больших объёмах | приемлемая альтернатива |

Структура бакета (бакет приватный, доступ только через короткоживущие presigned URL):

```
r2://content/
  projects/{projectId}/
    source/        исходные фото
    reference/     референсы
    images/        обработанные/сгенерированные изображения (с версиями)
    clips/         AI-видеоклипы
    audio/         озвучка + timestamps.json, музыка
    renders/       финальные ролики: master.mp4, ig.mp4, tt.mp4, tg.mp4, yt.mp4, subs.srt
```

**Данные публикаций** (статусы, ID постов, ссылки, ошибки, ответы API) хранятся в **PostgreSQL**, а не в файлах.

Политика хранения: промежуточные клипы и неудачные версии удаляются через N дней (правило жизненного цикла R2), финальные ролики и исходники остаются.

## 7. Контроль и ошибки

**Принцип:** каждый шаг конвейера — отдельная задача с сохранённым результатом. Правка одного элемента перезапускает только зависимые шаги: сменили голос → TTS → рендер; заменили картинку сцены 2 → клип сцены 2 → рендер. Остальное берётся из кэша, поэтому правки быстрые и дешёвые.

| Ситуация | Поведение |
|---|---|
| Ошибка генерации видео/изображения (таймаут, модерация, 5xx) | автоматический повтор с экспоненциальной задержкой (до 2–3 раз), затем статус «Ошибка» с текстом причины и кнопками «Повторить», «Изменить промпт», «Другая модель», «Заменить на анимированное фото» |
| Модерация провайдера отклонила промпт | показать причину, предложить отредактированный промпт (Claude перефразирует) |
| TTS не сработал | показать ошибку, предложить другой голос или запасного провайдера |
| Одна площадка упала при публикации | каждая площадка — **отдельная независимая задача**: TikTok упал → Instagram, Telegram и YouTube публикуются всё равно |
| Instagram не принял видео | статус контейнера (`status_code` = `ERROR`) и текст ошибки API показываются в журнале + кнопка «Повторить» |
| Истёк/отозван токен | статус «Требуется переподключение», уведомление, контент сохраняется, публикация повторяется после входа |
| Лимит площадки (IG 50/24ч, TikTok ~15/день, квота YouTube) | проверка до отправки, понятное сообщение, предложение отложить публикацию |
| Сбой посередине (воркер упал) | задачи идемпотентны (ключ = проект + площадка + версия рендера), чтобы не опубликовать дубль |
| Любая неудача публикации | контент и рендеры не удаляются, кнопка «Повторить публикацию» на конкретную площадку |

## 9. Безопасность

- **Секреты** (ключи Anthropic, Google, ElevenLabs, Kling, R2, client secret'ы площадок): только в переменных окружения. Локально — `.env` (в `.gitignore`, в репозитории только `.env.example` без значений). В продакшене — secrets manager хостинга (Docker secrets / Doppler / Infisical / Cloudflare secrets). **Никаких ключей в коде.** Сканер секретов в CI (gitleaks).
- **OAuth:** Authorization Code flow на сервере (+ PKCE, где поддерживается; TikTok его требует), проверка `state` от CSRF, минимальные scope'ы (`instagram_business_basic` + `instagram_business_content_publish`, `video.upload`/`video.publish` + `user.info.basic`, `youtube.upload`). Обмен на долгоживущие токены — **только на сервере** (там используется app secret).
- **Хранение токенов:** access/refresh-токены в БД **зашифрованы** (AES-256-GCM, ключ шифрования — отдельный секрет вне БД, в идеале KMS). Расшифровываются только в воркере публикации, никогда не уходят на фронт и не пишутся в логи (маскирование в логгере).
- **Обновление токенов:** задача по расписанию (Instagram — до истечения 60 дней; TikTok — refresh-токен; Google — приложение в статусе In production). Падение обновления → уведомление.
- **Доступ к системе:** один владелец; вход через passkey или Google OAuth с allow-list email; сессии httpOnly + secure cookies; rate limit на API; HTTPS везде.
- **Файлы:** бакет R2 приватный, ссылки — presigned URL с коротким сроком (для Instagram — около 1 часа, только на время публикации).
- **Данные:** фото людей — персональные данные. Не передавать их провайдерам, которые обучаются на данных API (проверить условия каждого AI-провайдера); политика удаления исходников; бэкапы БД зашифрованы.
- **Права:** у бота Telegram — только `can_post_messages`; ключи API — с ограничением по проекту и лимитом расходов (budget alerts в Google Cloud, лимиты в консоли Anthropic и ElevenLabs).

### 12.3 Рекомендуемый стек
- **Язык:** TypeScript везде.
- **Фронт и бэк:** Next.js + Tailwind + `@remotion/player`.
- **Очередь:** BullMQ + Redis.
- **БД:** PostgreSQL (Supabase или свой) + Prisma/Drizzle.
- **Хранилище:** Cloudflare R2.
- **LLM:** Claude (`claude-opus-5-5` в качественном режиме, `claude-sonnet-5-5`/`claude-haiku-5-5` в бюджетном), structured outputs.
- **Изображения:** Gemini Image (Nano Banana 2.1 / Pro) за адаптером.
- **Видео:** Veo 3.1 (Fast/Lite) + Kling 3.0 за адаптером.
- **TTS:** ElevenLabs (with-timestamps); запасной — OpenAI TTS + Forced Alignment.
- **Монтаж:** Remotion (рендер на воркере) + FFmpeg.
- **Деплой:** Docker на одном VPS (веб + воркер + Redis), Postgres и R2 — управляемые сервисы.

1. **Прототип конвейера без UI:** фото + референс → Claude-бриф → изображение → 1 клип → TTS → рендер Remotion. Цель — проверить качество на ваших реальных фото и выбрать модели.

### 12.9 MVP
- Один пользователь (вы), вход по паролю или passkey.
- Экран «Создать»: фото, референс, задание, язык, голос.
- Конвейер: Claude-бриф → (опционально) одна правка изображения в Gemini → **1 AI-клип (Veo) + анимированные фото** → ElevenLabs с таймкодами → **1 шаблон** Remotion с субтитрами → FFmpeg.
- Экран превью: просмотр; правка текста озвучки, субтитров и описаний; смена голоса; перегенерация сцены.
- Публикация: **Telegram + Instagram** (полностью автоматически), **YouTube** (загрузка, приватно до аудита), **TikTok** (режим Upload — в черновики).
- Журнал публикаций со ссылками и ошибками.
- Ключи в `.env`, токены в БД в зашифрованном виде.

### 12.10 Версия 2
- Direct Post в TikTok и публичный YouTube после одобрения аудитов.
- Несколько шаблонов и стилей, библиотека пресетов, музыка с автоматическим ducking.
- Второй видеопровайдер (Kling) и автоматический выбор/фолбэк.
- Отложенная публикация (календарь), карусели и Stories в Instagram.
- Мультиязычные версии одного ролика (RU/EN/AR одной кнопкой).
- Учёт расходов и аналитика по постам (Insights API площадок).
- Клонирование вашего голоса (ElevenLabs), загрузка своей озвучки + forced alignment.

### 12.11 Главные риски
1. **Аудиты TikTok и YouTube** могут затянуться или завершиться отказом, особенно для приложения «для себя». Без них «Опубликовать везде» работает полностью только для Telegram и Instagram.
2. **Качество и стабильность AI-видео:** артефакты, искажение лиц, «пластиковый» вид. Это главный риск для результата (не для техники) и главная статья расходов.
3. **Сохранение внешности** реального человека при редактировании фото.
4. **Изменения API и цен:** документация Meta уже противоречит сама себе по лимитам; цены на AI-видео быстро меняются (Kling анонсирует 4.0). Нужны адаптеры, а не жёсткая привязка к одному провайдеру.
5. **Политики платформ по AI-контенту:** обязательная маркировка AI-контента (TikTok, YouTube, Meta), риск пониженного охвата.
6. **Модерация провайдеров** может отклонять промпты или изображения с людьми.
7. **Токены:** незамеченное истечение (Instagram — 60 дней, Google — 7 дней в статусе Testing) ломает публикацию. Нужны мониторинг и уведомления.
8. **Права на музыку и референсы:** копирование чужого стиля допустимо, копирование чужого контента — нет.

### 12.12 Рекомендация

**Я рекомендую строить эту систему** — поэтапно, начиная с MVP.

Почему:
- Весь творческий конвейер (анализ → изображение → видео → голос → субтитры → монтаж → превью) реализуем **полностью на официальных API**, без серых схем.
- Telegram и Instagram публикуются полностью автоматически сразу. YouTube и TikTok — сразу в полуавтоматическом режиме (одно ручное действие), а после аудитов — полностью.
- Себестоимость ролика управляемая: от ~$0.65 до ~$5, и вы сами выбираете уровень качества.
- Архитектура с адаптерами защищает от быстрой смены AI-моделей и цен.

Условие: **подать на аудиты TikTok и YouTube в первый же день**. И принять, что ваш контроль на экране превью — не формальность, а необходимая часть процесса, потому что AI-видео пока не стабильно настолько, чтобы публиковать вслепую.
