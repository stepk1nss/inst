## 2. Секретные поля: как ответ физически не попадает к генератору тизера

Это **общий механизм ядра**, а не код под «Зазеркалье». Он подходит для любой механики «тизер здесь, раскрытие там»: викторины, загадки, «угадай место», спойлеры.

### 2.1 Три правила

1. **Поле может быть секретным:** `secret: true` в описании поля сценария.
2. **Шаг видит секреты, только если это явно разрешено** (`sees.secrets: true`). По умолчанию — нет. Ядро собирает входные данные для шага само и **вырезает** из них все секретные поля. Шаг не может их запросить, потому что не получает к ним доступа.
3. **Правило заражения (taint).** Всё, что произвёл шаг, видевший секреты, автоматически считается секретным. Если в конфиге такой шаг объявляет несекретное выходное поле, **конфиг не загрузится** и бот покажет ошибку. Так секрет не может «утечь» через промежуточное поле.

И для площадок:

4. **Площадка видит секреты, только если `reveal_secrets: true`.** Шаблон площадки без этого флага, который ссылается на секретное поле, — это ошибка загрузки конфига, а не тихая утечка в 3 часа ночи.

### 2.2 Как это выглядит для сценария ПДД

```
             ┌──────────────────────────── картинка билета ─────────────────────────────┐
             ▼                                                                          ▼
 [extract] видит: картинку                                      [solve] видит: картинку + question, options
           НЕ видит секретов                                            sees.secrets: true
           → question, options, situation   (открытые)                  → correct, explanation, rule_ref,
             │                                                             uncertain     (СЕКРЕТНЫЕ)
             │                                                                │
             ▼                                                                ▼
 [teaser]  видит: ТОЛЬКО question + situation                    [telegram_post] видит всё
           без картинки (media: false), без секретов                      → tg_text (секретное по taint)
           → teaser, voiceover, ig/tt/yt тексты, хэштеги                       │
             │                                                                │
             ▼                                                                ▼
 Instagram / TikTok / YouTube  (reveal_secrets: false)          Telegram  (reveal_secrets: true)
```

Почему генератор тизера **не получает картинку и варианты ответов**: если дать модели вопрос с вариантами, она может сама решить билет и намекнуть на ответ. Поэтому изоляция данных — первый уровень защиты, а не единственный.

### 2.3 Уровни защиты

| Уровень | Что делает | Ловит |
|---|---|---|
| 1. Изоляция данных (ядро) | генератор тизера не получает `correct`, `explanation`, `rule_ref`, картинку и варианты | основную утечку — модели нечего раскрывать |
| 2. Проверка конфига (при загрузке) | правила 3–4: заражение и `reveal_secrets` | ошибку автора конфига |
| 3. Детерминированная проверка утечки (`validate`) | ищет текст правильного варианта, его номер/букву («ответ 2», «вариант Б») и т. п. во всех открытых текстах и озвучке | случайное совпадение |
| 4. LLM-судья (дешёвая модель, опционально) | получает ответ + тизер и возвращает **только да/нет**: «раскрывает ли текст ответ?» Сам ничего не пишет, его выход в тексты не попадает | намёки («подумай про помеху справа») |
| 5. Превью | вы видите все тексты перед публикацией | всё остальное |

Если уровень 3 или 4 сработал, пост **не публикуется даже в режиме Авто**: он переходит в «Подтверждение» с пометкой «⚠️ возможная утечка ответа» и кнопкой «Перегенерировать тизер».

Если `solve` вернул `uncertain: true` (модель не уверена в ответе), действует то же правило: публикация только после вашего подтверждения.

## 3. Пользовательский поток в боте

```
1. Вы → фото (подпись необязательна: можно указать #проект, #сценарий или факты — адрес, часы)
2. Бот: «Проект?»  [🪞 Зазеркалье ⭐последний] [🏙 Петербург] [➕ Новый]
       — шаг пропускается, если в подписи есть #тег проекта
3. Бот (через 1–3 с, дешёвый classify): «Сценарий?»
       [✅ 🎫 Билет ПДД (авто)] [📝 Обычный пост] [ещё…]
       — нажатие любой кнопки сразу запускает генерацию
       — если у проекта один сценарий или сценарий указан #тегом в подписи, шаг пропускается
4. Генерация: прогресс одним сообщением (анализ ✓ → тексты ✓ → озвучка ✓ → видео ✓)
5. Превью:
     • видео (или фото) + голосовое сообщение с озвучкой
     • карточка текстов с вкладками-кнопками: [Telegram] [Instagram] [TikTok] [YouTube]
     • предупреждения (⚠️ ответ сомнительный / ⚠️ возможная утечка)
     • куда уйдёт пост: @канал (TG) · @аккаунт (IG) · …
     [✅ Опубликовать] [💾 Черновик] [🎙 Голос] [✏️ Правка] [🔁 Перегенерировать] [❌]
6. Публикация → отчёт: ✅ Telegram [ссылка] · ✅ Instagram [ссылка] · ⏳ TikTok (черновик) · 🔒 YouTube (приватно)
```

Кнопки шагов 2–3 работают в один тап. Минимальный путь: фото → проект → сценарий → «Опубликовать» = **3 нажатия**. С `#тегом` в подписи — одно.

### Режимы публикации

| Режим | Что происходит после генерации |
|---|---|
| **Черновик** | пост сохраняется, ничего не публикуется. `/drafts` → открыть → то же превью → опубликовать позже |
| **Подтверждение** (по умолчанию) | превью, публикация только по кнопке |
| **Авто** | публикуется сразу, вам приходит отчёт. **Принудительно переходит в «Подтверждение»**, если сработала любая проверка (`uncertain`, утечка, ошибка валидации площадки) |

Режим по умолчанию задаётся в проекте. Для конкретного поста его можно сменить кнопкой в превью или тегом в подписи (`#черновик`).

## 4. Голос и частичная перегенерация

### 4.1 Граф зависимостей шагов

Каждый шаг объявляет свои входы. Ядро хранит результат каждого шага с ключом от его входов (хэш) и при изменении перезапускает **только зависимые** шаги:

```
media ─► extract ─► solve ─────────────► telegram_post ─► compose ─► validate ─► (publish)
              └───► teaser ─► voiceover ─► tts ─► render_video ─┘
                                            ▲
                                  voice_id, speed  (параметры поста)
```

| Что вы меняете | Что перезапускается | Цена |
|---|---|---|
| **Голос / скорость** | `tts` → `render_video` → `compose` → `validate` | только TTS (~$0.01–0.05), Claude не вызывается |
| Текст озвучки (правка вручную) | `tts` → `render_video` → `validate` | только TTS |
| Текст одной площадки (вручную) | `validate` | $0 |
| «Перегенерировать тизер» | `teaser` → `tts` → `render_video` → … | Claude + TTS |
| Сценарий | всё | полная генерация |

### 4.2 Выбор и прослушивание голоса

- В проекте задаются `voice.default` и `voice.allowed` — список голосов на выбор (имя, ID ElevenLabs, короткое описание).
- `🎙 Голос` в превью → список голосов. У каждого кнопка **▶ образец** (заранее сгенерированный короткий сэмпл, кэшируется один раз) и **выбрать**.
- После выбора приходят **новое голосовое сообщение и обновлённое видео**. Тексты не меняются.
- Озвучка в превью отправляется голосовым сообщением Telegram, его можно слушать прямо в чате.

## 5. Финальный состав MVP

### 5.1 Входит

**Ядро**
- Загрузка и валидация конфигурации: система, шаблоны, проекты; наследование `extends`; проверки секретности (раздел 2) и ссылок (несуществующий шаг, поле, площадка → понятная ошибка).
- Движок конвейера: шаги, граф зависимостей, кэш результатов, частичная перегенерация.
- Секретные поля, изоляция входов шагов, правило заражения.
- Динамическая JSON Schema из полей сценария → structured outputs Claude.

**Шаги** (реестр ядра)
`ingest` · `classify` · `generate` (универсальный LLM-шаг) · `tts` · `render_video` · `compose` · `validate` (длины, лимиты площадок, утечка секретов, LLM-судья) · `publish`. Плюс интерфейс `enrich` без реализаций.

**Бот**
- Приём фото (альбомы и видео на входе — во второй очереди).
- Выбор проекта (последний первым, `#теги`), выбор сценария перед генерацией.
- Превью с вкладками площадок; голосовое сообщение; смена голоса с образцами; правка текста (ответом на сообщение: Claude применяет правку только к выбранному полю); три режима публикации; `/drafts`.
- Служебные команды: `/projects`, `/reload` (перечитать конфиги), `/new_project` (минимальный), `/connect <площадка>` (OAuth-ссылка), `/log` (последние публикации).
- Доступ только для вашего Telegram user_id.

**Площадки** (по очереди, см. 5.3)
- Telegram: фото + подпись / видео; текст > 1024 символов — отдельным сообщением.
- Instagram: пост-картинка (JPEG, дополнение полями до 4:5) или Reels (видеообёртка).
- TikTok: режим черновика (`MEDIA_UPLOAD`) до аудита; прямая публикация включается флагом после аудита.
- YouTube: загрузка Shorts (до аудита — приватно).

**Инфраструктура**
- Хранилище R2 (публичные ссылки для Instagram/TikTok), SQLite (посты, результаты шагов, публикации, токены, журнал).
- Токены соцсетей в зашифрованном виде; ключи только в `.env`.
- Обновление токенов по расписанию; повтор публикации на одной площадке; журнал с сырыми ответами API.

**Проекты и шаблоны в MVP**
- Шаблоны: `quiz_teaser` (тизер + раскрытие), `place` (место, без `enrich`), `simple_post` (по умолчанию для новых проектов).
- Проекты: `zazerkalye` (сценарии `pdd_ticket`, `simple`), `spb` (сценарии `venue`, `building`, `simple`) — второй проект нужен как доказательство, что ядро не заточено под первый.

### 5.2 Не входит (следующие версии)

Видео и альбомы на входе (`extract_video`), реализации `enrich` (адреса, часы, карты), обработка изображения по референсу (Gemini Image), диалоги нескольких персонажей в озвучке, субтитры, фоновая музыка, расписание и очередь публикаций, полноценный конструктор `/new_project`, веб-панель, аналитика, проект «Приложения» и шаблон `ad_promo`.

### 5.3 Порядок реализации

| Этап | Результат, который можно проверить |
|---|---|
| **M1. Каркас** | конфиги грузятся и валидируются; тесты секретности проходят; конвейер работает из командной строки на тестовом фото |
| **M2. Генерация в боте** | фото → проект → сценарий → превью с текстами, голосом и видео; смена голоса; правки. **Без публикации** |
| **M3. Публикация (основные)** | Telegram + Instagram; режимы Черновик/Подтверждение/Авто; журнал; повторы |
| **M4. Публикация (до аудита)** | TikTok (черновики) + YouTube (приватно); обновление токенов |
| **M5. Универсальность** | проект `spb` + минимальный `/new_project` + `/test` |

После каждого этапа — короткая проверка с вами на реальных картинках.

## 6. `/new_project` (минимальный)

```
/new_project
→ Бот: «Опишите проект одним сообщением или пришлите YAML»
→ Claude превращает описание в YAML на основе шаблона simple_post (или указанного шаблона)
→ ядро валидирует; при ошибке Claude исправляет (до 2 попыток)
→ Бот показывает YAML-сводку: [✅ Сохранить] [❌]
→ сохраняется в projects/<id>/project.yaml, проект сразу появляется в списке
```

Без пошаговых мастеров, без редактора в боте. Правка — через файл и `/reload`.

## 7. Точка расширения для внешних источников

```yaml
fields:
  address: {type: string, source: caption}          # MVP: только из вашей подписи, иначе пусто
  # в будущем:
  # address: {type: string, source: enrich.maps, verify: true}
```

- `source: caption` — Claude извлекает значение **только из вашей подписи**. Если там ничего нет, поле остаётся пустым и в пост не попадает. Выдумывать запрещено инструкцией и проверяется: значение должно встречаться в подписи.
- `source: enrich.<provider>` — в будущем шаг-плагин (карты, веб-поиск) с обязательной пометкой «проверить». Схема конфига уже допускает это значение, ядро менять не нужно: достаточно добавить модуль в `steps/enrich/`.

```yaml
id: quiz_teaser
description: Вопрос-тизер без ответа в соцсетях + полное раскрытие там, где reveal_secrets
fields:
  question:    {type: string,  desc: "Вопрос своими словами"}
  options:     {type: array, items: string, desc: "Варианты ответа, если есть"}
  situation:   {type: string,  desc: "Описание ситуации без подсказок к ответу"}
  correct:     {type: string,  secret: true, desc: "Правильный ответ"}
  explanation: {type: string,  secret: true, desc: "Объяснение"}
  uncertain:   {type: boolean, secret: true, desc: "Есть сомнения в ответе"}
  teaser:      {type: string,  desc: "Хук-вопрос без ответа"}
  voiceover:   {type: string,  desc: "Текст озвучки без ответа"}
  full_post:   {type: string,  secret: true, desc: "Полный пост с ответом"}

steps:
  - id: extract
    use: generate
    sees: {media: true}                        # секретов не видит (по умолчанию)
    produces: [question, options, situation]
    instructions: "Перенеси вопрос и варианты. НЕ решай и не оценивай варианты."

  - id: solve
    use: generate
    sees: {media: true, fields: [question, options], secrets: true}
    produces: [correct, explanation, uncertain]   # все секретные — иначе ошибка загрузки (taint)

  - id: teaser
    use: generate
    sees: {media: false, fields: [question, situation]}   # без картинки, без вариантов, без секретов
    produces: [teaser, voiceover, platform_texts]

  - id: full
    use: generate
    sees: {fields: all, secrets: true}
    produces: [full_post]

  - id: tts
    use: tts
    input: voiceover

  - id: video
    use: render_video

  - id: validate
    use: validate
    checks:
      - no_secret_leak: {secrets: [correct], judge: true}
      - block_auto_if: {field: uncertain, equals: true, message: "Ответ сомнительный — проверьте"}

platform_defaults:
  telegram:  {reveal_secrets: true,  template: "{{ full_post }}"}
  instagram: {reveal_secrets: false, text_from: platform_texts.instagram}
  tiktok:    {reveal_secrets: false, text_from: platform_texts.tiktok}
  youtube:   {reveal_secrets: false, text_from: platform_texts.youtube}
```

`platform_texts` — составное поле: шаг `teaser` возвращает отдельный объект для каждой включённой площадки (подпись, хэштеги, CTA; для YouTube — заголовок и описание). Правила каждой площадки (лимиты длины, число хэштегов) ядро подставляет в инструкцию автоматически из адаптера площадки.

## 9a. Ручная проверка неуверенного ответа (решение 2026-10-09, вариант «а»)

Общий механизм ядра: проверка сценария `type: require_review_if` (поле, значение, сообщение, подпись кнопки). Для `quiz_teaser`: `uncertain = true` → «✅ Я проверил ответ».

- Пока проверка не отмечена, «Подтвердить» недоступна — и в боте, и в ядре (`approve` отказывает), в режимах «Подтверждение» и «Авто». В «Авто» публикация останавливается и переходит в ручное подтверждение.
- Пост можно исправить или перегенерировать: правки текста, «🔁 Перепроверить» (перезапуск шага, который выставил флаг), «🔁 Тексты заново», смена сценария.
- «Я проверил ответ» записывает в журнал (`events` в `state.json`) кто и когда проверил; после этого доступно ручное подтверждение. Сама проверка ничего не публикует, даже в «Авто».
- Подтверждение тоже пишется в журнал: `approved`, `by`, `manual_review`, `reviewed_by`.
- Если после проверки изменились секретные поля (например, ответ перегенерирован с другим результатом), проверка сбрасывается (`review_reset`) и нужна заново. Смена голоса или текстов тизера проверку не сбрасывает.

## 10. Ответы на вопросы (2026-10-09) и как они реализованы

| Решение | Реализация в M1 |
|---|---|
| Голоса не окончательные | ID голосов — переменные окружения (`VOICE_BATRAKAN` и т. д.) или поле `provider_voice_id`; пустой ID → временный голос `ELEVENLABS_FALLBACK_VOICE_ID`; голос меняется для поста без перегенерации текстов |
| Telegram ПДД: билет + все варианты + ответ под спойлером + объяснение и пункт ПДД | шаблон `telegram` в `projects/zazerkalye/project.yaml`. Объяснение и пункт ПДД тоже под спойлером — иначе они раскрывают ответ; если нужно открыто, это правка шаблона, не кода |
| Все 4 площадки | включены; TikTok — `mode: draft`, YouTube — `visibility: private` до аудитов |
| Без сервера и домена | всё работает локально; OAuth, R2 и реальная публикация — после M2 |
| Материалы позже | `projects/zazerkalye/prompts/*.md` — заглушки с пометкой `PLACEHOLDER`, бот/CLI предупреждает о них |
| Dev/test режим без ключей | `CONTENTBOT_MODE=dev`: mock-LLM (ответы из YAML-фикстур), mock-голос (тон через FFmpeg), публикация — только dry-run в `outbox/` |
